# CLAUDE.md: Chasqui

WhatsApp relay for Neorgon, a proof of concept: the window triggers an AiSensy API campaign for one number through a Convex action and shows every send, refusal and inbound webhook event in a live thread. For the operator deciding whether WhatsApp belongs in the fleet.

**Live:** chasqui.neorgon.com · **Port:** 8890

## Run

```bash
make serve      # http://localhost:8890
npx convex dev  # backend; the dev deployment is in .env.local (deafening-chameleon-255)
make test       # node --test over convex/lib/phone.ts
```

Then open http://localhost:8890. It must be served over HTTP: the app is ES modules, and `file://` blocks them.

- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- No single JS file over ~500 lines. It currently holds.

## Gotchas

- **The free AiSensy plan cannot send.** The key on the deployment is a Forever Free key
  and AiSensy answers every campaign call with `400 No Plan active on assistant!`. That
  is the provider, not this code: the same request succeeds once the plan includes API
  campaigns. The thread shows the body verbatim so nobody debugs the relay for it.
- **Secrets live only on the deployment.** `AISENSY_API_KEY` and `AISENSY_WEBHOOK_TOKEN`
  are read with `process.env` inside `convex/`; `config:status` reports booleans only.
  The site repo is public, so never write either into `js/`, the README or a test.
  Verify a value with `npx convex env get NAME | shasum`, never `env list`.
- **`aisensy:send` is public.** The deployment URL ships in `js/data.js`, so anyone can
  call the action. What bounds abuse is `rateLimit.ts` (5 per number per hour, 40 per
  day globally) and the optional `AISENSY_ALLOWED_DESTINATIONS` allowlist. Do not remove
  the limits to "simplify" the action.
- **A number without a country code is refused on purpose.** AiSensy resolves one to
  India (+91) by default. `normalizeE164` in `convex/lib/phone.ts` is the authority; the
  copy in `js/utils.js` only decides whether the Send button lights up.
- **Threads are readable by number.** `messages:thread` takes a phone and returns its
  history, so anyone who knows a number can read what the relay sent it. Accepted for a
  proof of concept; a real deployment would put the Auth Kit in front of it.
- **The webhook trusts a token in the URL.** AiSensy documents no signature, so
  `/aisensy/webhook?token=…` on the `.convex.site` host is the whole check, and it fails
  closed (503) when the token is unset. Payload shape is unknown; `extractInbound`
  guesses the sender and text and keeps the raw body in `detail`.
- **Never `npm install` from a workspace member.** This project is not in the root
  `workspaces` list, so `npm install` here is local (`npm prefix` prints this folder).
  Typecheck with `npx -p typescript@5.6.3 tsc --noEmit -p convex/tsconfig.json`.
